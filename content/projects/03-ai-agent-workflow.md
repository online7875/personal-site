## 背景

团队每天有大量"读文件、抽字段、写材料"的重复动作：对账文件清洗、简历初筛、周报汇总、文档改写。

这类事用传统脚本做不划算（格式天天变），用纯人工做又浪费人。Agent 看起来是个解法，但直接让模型自己跑，错一次就没人敢用。

## 我做了什么

- 选了三类高频场景做试点，先跑通一条最短链路，再考虑泛化。
- 把任务拆成"读取 → 抽取 → 校验 → 生成 → 人工确认"几步，每一步都有明确的输入输出契约。
- 给 Agent 注册少量高价值的工具（文件解析、SQL 查询、模板渲染），而不是开放全部能力。
- 建了一套简单的评测集：固定输入、固定期望，每次改提示词都跑一遍。

## 关键设计

- **人在回路**：所有会对外产生影响的动作（发消息、写库、提交表单）必须人工确认。
- **工具而不是自由发挥**：模型只在给定工具集内选择，结果可控。
- **可观测**：每一步的输入、输出、耗时都落库，出问题能回放。
- **评测先行**：没有评测集的提示词改动，一律不上线。

## 沉淀

- 一套最小可用的 Agent 工作流模板（任务定义 + 工具注册 + 人工确认 + 评测）。
- 几条踩过的坑：上下文塞太满反而变差、工具描述写得含糊模型就乱调用、没有兜底就不要自动化。
